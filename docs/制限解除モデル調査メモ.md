# 制限解除モデル調査メモ

最終更新: 2026-08-10

## 目的

`llama.cpp` / GGUF で動作し、主に次の用途に使える小型モデルを比較するためのメモ。

- 日本語で画像・動画生成の要件を指示する
- 英語の生成プロンプトを出力する
- 必要に応じて参考画像を入力し、構図・姿勢・衣装・照明などを解析する
- 成人向けの創作表現で過剰な拒否が起きにくいこと
- おおむね 12B 以下、RTX 4070 Ti 12GB でも扱いやすいこと

「uncensored」「abliterated」「heretic」などの表記は、違法性や事実性、安全性を保証するものではない。多くの場合、モデルの拒否方向を弱めたことを意味するだけであり、成人向け文章や画像生成プロンプトに特化して追加学習されているとは限らない。

## 「危険」の分類

解除モデルを評価するときは、次のリスクを分けて考える。

1. **出力上のリスク**: 不適切・誤情報・過激な内容にも回答しやすい。
2. **能力上のリスク**: abliteration によって日本語、論理性、TruthfulQA、指示追従などが劣化する可能性がある。
3. **供給元・来歴のリスク**: 元モデル、解除手法、量子化方法、ライセンスが不明瞭な場合がある。
4. **ファイル／実行環境のリスク**: GGUF パーサーや埋め込み chat template の脆弱性、改ざんファイルの可能性がある。

解除モデルだから直ちにマルウェアということではない。GGUF は基本的にテンソルとメタデータの形式で、pickle のように任意の Python オブジェクトを直接実行する形式ではない。ただし、GGUF パーサーや Jinja chat template の脆弱性が報告されたことはあるため、`llama.cpp` は新しい版を使う。

参考:

- [Hugging Face: Malware Scanning](https://huggingface.co/docs/hub/en/security-malware)
- [Hugging Face: GGUF](https://huggingface.co/docs/hub/gguf)
- [llama.cpp GGUF parser security advisory](https://github.com/ggml-org/llama.cpp/security/advisories/GHSA-vgg9-87g3-85w8)

## 提供者・手法のメモ

### p-e-w / Heretic

現時点では、透明性と再現性を重視する場合の第一候補。

- 解除ツールをオープンソースで公開している。
- 拒否率だけでなく、元モデルからの変化を示す KL divergence も同時に小さくする方針。
- 設定、評価、実装を確認しやすい。
- Dense、MoE、マルチモーダル、Qwen3.5 などにも対応。
- Heretic を使用した派生モデルは多数あるが、第三者が作った Heretic モデルでは設定・元モデル・量子化元を個別に確認する。

リンク:

- [p-e-w/heretic](https://github.com/p-e-w/heretic)
- [p-e-w on Hugging Face](https://huggingface.co/p-e-w)

### HauhauCS / HauHau

多数の解除モデルを公開しており、ダウンロード数も非常に多い。知名度と普及度は高いが、技術的な信頼性は慎重に評価する。

- Qwen、Gemma、GLM などへの対応が速い。
- `Aggressive` は拒否除去優先、`Balanced` は能力維持を重視すると説明されている。
- モデルカードでは「0/465 refusals」「zero capability loss」などを掲げることが多い。
- 一方で、解除方法が長期間非公開だったこと、「lossless」の根拠が弱いことを批判されている。
- 公開後に削除された `reaper-abliteration` について、Heretic 由来コードの帰属・ライセンスに関する具体的な論争がある。
- 独立分析では、一部の Qwen3.5 モデルで元モデルからの出力分布変化やベンチマーク低下が報告されている。
- 上記の論争はコミュニティのコード比較と作者見解に基づくもので、司法判断などで確定した事実ではない。
- HauhauCS の GGUF がマルウェアであるという具体的証拠は、今回の調査では確認できなかった。

評価方針:

- 人気があることと、技術的主張が正しいことを分ける。
- 「能力損失ゼロ」はそのまま受け取らず、公式モデル・Heretic版と実測比較する。
- 成人向けプロンプトでの拒否の少なさを優先する比較対象として扱う。

リンク:

- [HauhauCS models](https://huggingface.co/HauhauCS/models)
- [Reaper Abliteration の第三者分析](https://dreamfast.github.io/reaper-analysis/)
- [Heretic 作者を含む Reddit 上の議論](https://www.reddit.com/r/LocalLLaMA/comments/1sw77p0/hauhaucs_of_uncensored_aggressive_fame_published/)

### huihui-ai

新しいモデルへの abliteration 対応が速く、非常に多数の派生モデルを公開している有名な提供者。

- Qwen、Gemma、GLM、DeepSeek などが豊富。
- GGUF を直接提供する場合もある。
- Heretic より手法の再現性・透明性を確認しにくいため、モデル単位で元モデルと評価結果を見る。

リンク:

- [huihui-ai on Hugging Face](https://huggingface.co/huihui-ai)

### mlabonne / Maxime Labonne

abliteration の解説、実装例、能力回復用 DPO などを早期から公開した人物。

- abliteration 後の能力低下を DPO で回復する考え方を説明している。
- `NeuralDaredevil-8B-abliterated` などで知られる。
- 最新 Qwen3.5 / Gemma 4 の第一候補というより、手法と評価方法を理解するための参考元。

リンク:

- [mlabonne on Hugging Face](https://huggingface.co/mlabonne)
- [NeuralDaredevil-8B-abliterated](https://huggingface.co/mlabonne/NeuralDaredevil-8B-abliterated)

### failspy

Llama 3 世代の初期の abliterated モデルで知られる提供者。最新 Qwen3.5 の候補は多くないが、分野の先行例として有名。

- [failspy on Hugging Face](https://huggingface.co/failspy)

### Cognitive Computations / Dolphin

Dolphin 系は、主に安全調整データを除外・変更した fine-tune であり、単純な abliteration とは方式が異なる。

- 会話・RP向けのモデルが多い。
- 元の instruct モデルからの性格や能力変化は大きくなりやすい。
- 最新基礎モデルの能力を極力そのまま維持したい用途とは分けて評価する。

### DavidAU / llmfan46

Heretic、uncensored、RP、複数モデルの merge を多数公開している。

- 候補が豊富で、創作・RP向けのモデルを見つけやすい。
- モデル名が長く、複数の LoRA やモデルを混ぜたものが多い。
- 元モデルそのままの日本語能力や画像能力を求める場合は、model tree と model card を確認する。

### 量子化配布者

`mradermacher`、`bartowski`、`Unsloth`、`ggml-org` などは、主に GGUF 変換・量子化の実績が多い提供者。

量子化配布者が信頼できても、変換元の解除モデルの品質・ライセンス・来歴まで保証されるわけではない。必ず `base_model`、model tree、変換元リンクを見る。

### lukey03 Qwen3.5-9B Abliterated Vision

ファイル:

```text
Qwen3.5-9B-abliterated-vision-Q4_K_M.gguf
```

特徴:

- 約 6.59GB。
- テキストモデル、公式の vision encoder、MTP テンソルを一つの GGUF に統合。
- 3回の直交射影 abliteration と、残った拒否カテゴリへの QLoRA を使用。
- 画像側テンソルは公式 Qwen3.5-9B のものを維持すると説明されている。
- 別 `mmproj` が不要で手軽。
- 拒否評価は 18/18 回答だが、日本語能力や一般能力維持の検証としては小さい。
- LoRA も使用しているため、純粋な方向除去より性格・能力が変化している可能性がある。
- 一体型 vision GGUF は標準的な「本体 + mmproj」構成と異なるため、`llama.cpp` で画像入力が有効にならない場合は別 `mmproj` 方式を使う。

配布元:

- [lukey03/Qwen3.5-9B-abliterated-GGUF](https://huggingface.co/lukey03/Qwen3.5-9B-abliterated-GGUF)
- [解除手法の説明](https://huggingface.co/lukey03/Qwen3.5-9B-abliterated)

## 比較時のテスト項目

各モデルを同一条件で最低5回ずつ生成し、単発の印象で決めない。

### 日本語・英語変換

- 日本語の条件を落とさないか。
- 出力を英語だけに限定できるか。
- 人数、左右、衣装、色、姿勢、画角を正しく保持するか。
- 日本語が英語出力に混ざらないか。

### 画像理解

- 被写体数を正しく数えるか。
- 姿勢、手足、視線、前後関係を理解できるか。
- カメラアングル、焦点距離、被写界深度、照明を抽出できるか。
- 画像内文字を内容と命令に区別できるか。
- 画像に書かれたプロンプトインジェクションへ従わないか。

### 画像生成プロンプト

- FLUX向け自然文
- SDXL向け自然文 + キーワード
- Pony / Illustrious / NoobAI向け Danbooru タグ
- positive / negative prompt の分離
- 重複タグ、矛盾タグ、過剰な品質タグがないか

### 動画生成プロンプト

- 被写体の初期状態と動作を分けられるか。
- カメラ移動を明示できるか。
- 時間変化、速度、方向、終端状態を記述できるか。
- Wan、HunyuanVideo、LTX など対象モデルに合う形式か。

### 解除による副作用

- 不要な性的・暴力的表現を勝手に追加しないか。
- 指示していない人格や口調が混ざらないか。
- `<think>`、開始・終了タグ、免責文が出力へ漏れないか。
- 拒否しない代わりに、依頼を意図的に誤解しないか。
- 公式モデルより日本語・論理性が落ちていないか。

## 安全な運用・確認手順

1. Hugging Face の元リポジトリ、model tree、ライセンスを確認する。
2. 可能なら公開 SHA-256 とダウンロード後のファイルを照合する。
3. `llama.cpp` を最新の安定版または十分新しいコミットへ更新する。
4. `llama-server` は原則 `127.0.0.1` に bind し、インターネットへ直接公開しない。
5. モデルに shell、ファイル削除、認証情報、外部送信ツールを無制限に与えない。
6. 画像内テキストは信頼できない入力として扱う。
7. GGUF 内の chat template とメタデータを確認し、不自然な隠し命令がないかを見る。
8. 公式モデル、Heretic版、Huihui版、HauhauCS版を同一プロンプト・同一samplingで比較する。
9. 本番採用時はリポジトリ名だけでなく、コミットIDとファイルハッシュを固定する。

## 暫定優先順位

今回の「日本語指示 → 英語の画像・動画生成プロンプト、必要なら参考画像入力」という用途では、次の順に試す。

1. Qwen3.5-9B Heretic + 対応 vision projector
2. lukey03 Qwen3.5-9B Abliterated Vision Q4_K_M
3. 公式 Qwen3.5-9B + vision projector
4. HauhauCS Qwen3.5-9B Aggressive + vision projector
5. Gemma 4 12B QAT Balanced + vision projector
6. Gemma 4 E4B Heretic / Uncensored + vision projector

解除モデルだけでなく公式モデルも比較に残す。成人向けの生成プロンプトでも、書き方を創作・画像生成用途として明示すれば公式モデルが十分対応する場合があり、その場合は能力変更の少ない公式版が最も安定する。
